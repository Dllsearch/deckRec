# Восстановление SteamOS

[English documentation](README.md)

Комплект восстанавливает все сохранённые пакеты pacman, включая готовые бинарные
пакеты AUR и сторонние пакеты. Сборщик сохраняет **точные установленные версии**:
это снимок работающей системы, а не обновление SteamOS до произвольного Arch Linux.

Запуск из проводника — двойным щелчком по **Deck Recovery.desktop**: меню
открывается в терминале. Если KDE спросит, разрешите запуск доверенного ярлыка.
При запуске `rec.sh` без терминала он сам открывает отдельное окно Konsole.

Основной запуск — `./rec.sh` **без sudo**. Меню управляется стрелками или W/S,
компоненты выбираются пробелом либо цифрами, Enter запускает выбранные операции.
Esc/Q возвращает назад. На Steam Deck со стандартной Desktop-раскладкой Steam:
крестовина ↑↓ — навигация, A — Enter, B — назад, Y — отметить компонент.
STEAM+X открывает экранную клавиатуру для пути и пароля sudo.
Для home перед бэкапом закройте приложения.

```bash
./rec.sh
./rec.sh --status
./rec.sh --backup backups/другой-снимок
```

В корне оставлены меню и документация. Рабочие скрипты и помощники интерфейса
находятся в `scripts/`, тесты — в `tests/`, действующий снимок — в
`backups/current/`. В снимке есть собственные `rec.sh` и `scripts/`, чтобы его
можно было перенести и использовать отдельно. `pacs` — ссылка на сохранённые
пакеты `backups/current/packages`. `incoming/` — отдельные архивы пакетов вне
индекса снимка; сборщик ищет там точные установленные версии. Перенос файла в
`incoming/` сам по себе не добавляет его в снимок.

Меню позволяет сохранить пакеты, home и системные настройки по отдельности или
вместе. Восстанавливает пакеты и отсутствующие файлы home. Все файлы снимка (включая `packages/repo`, `packages/foreign`, метаданные и
журналы) доступны через «Просмотреть все файлы бэкапа и размеры». По умолчанию
служебные скрипты, метаданные и журналы скрыты: Y / пробел или A на галочке
«Показать служебные файлы» включает их. В заголовке показан общий размер текущей
папки, включая скрытые служебные файлы. Текстовые файлы
можно читать с прокруткой; для больших файлов показываются первые 64 КиБ.
Архивы открываются встроенным просмотрщиком: A открывает папку, B возвращает назад
и выходит из корня. Видны размеры файлов и суммарный несжатый объём папок.
Автоматического восстановления всего `/etc` нет.
Выбор каталога снимка не изменяет файлы, пока не запущена операция.

## Назначение скриптов

| Скрипт | Для чего |
| --- | --- |
| `restore-all.sh` | Восстанавливает пакеты; с `--with-settings` также добавляет отсутствующие файлы home. |
| `restore-system.sh` | Проверяет снимок и восстанавливает пакеты офлайн; перед установкой включает devmode и снимает readonly SteamOS. `--dry-run` только проверяет. |
| `restore-settings.sh` | Восстанавливает отсутствующие настройки и данные home, не заменяя существующие файлы. |
| `backup-packages.py` | Сохраняет архивы точных установленных версий пакетов и их контрольные суммы. |
| `backup-settings.sh` | Архивирует скрытые настройки и данные home, исключая игры и основные кэши. |
| `backup-empty-files.py` | Вспомогательный скрипт для `backup-settings.sh`: сохраняет метаданные нечитаемых пустых файлов Steam. |
| `backup-system.sh` | Архивирует выбранные системные папки; `/etc` включён, `/usr/local` и Flatpak настраиваются. Требует sudo. |
| `fix-steamdeck-power-button.sh` | Настраивает сон по короткому нажатию кнопки питания; `status` проверяет, `remove` удаляет настройку. После изменения нужна перезагрузка. |

Копии `scripts/` в снимке обновляются при сборе пакетов.

## Установка одной командой

Из каталога `rec`:

```bash
./scripts/restore-all.sh --yes
```

Для восстановления также отсутствующих файлов домашнего каталога:

```bash
./scripts/restore-all.sh --yes --with-settings
```

Запускать от обычного пользователя. Для пакетов скрипт сам вызовет sudo.
Существующие настройки и аккаунты в home сохраняются. `--with-settings` добавляет
только отсутствующие файлы; существующие файлы не заменяет. Это не откат состояния
приложений к моменту снимка. Перед восстановлением настроек закройте приложения.
Системный архив `/etc` автоматически не распаковывается поверх новой SteamOS.

Предварительная проверка без установки и без sudo:

```bash
./scripts/restore-system.sh --dry-run
```

Другой снимок: добавьте `--backup /путь/к/снимку`.

## Что делает установка

- Проверяет SHA256 всех архивов и метаданные пакетов.
- Сравнивает установленную и сохранённую версии через `vercmp`, учитывая epoch и pkgrel.
- Пропускает равные и более новые установленные версии. Не делает downgrade.
- Устанавливает недостающие/более новые пакеты одной транзакцией `pacman -U`.
- Сохраняет `--overwrite '*'` для восстановления поверх оставшихся файлов.
- Не запускает `pacman -Syu`, yay, скачивание или сборку из AUR при восстановлении.
- При наличии `steamos-devmode` включает режим разработчика (эквивалент `sudo steamos-devmode enable`); ошибка включения останавливает восстановление.
- При необходимости отключает readonly SteamOS и расширяет `/`, только если это Btrfs.
- Сохраняет статус зависимостей для вновь установленных пакетов.

`--overwrite` обходит конфликты файлов, но не несовместимые зависимости и не
конфликты «файл вместо каталога». Проверка зависимостей pacman остаётся включённой.
После смены SteamOS старые сторонние пакеты могут требовать пересборки под новые
библиотеки; скрипт в таком случае сообщит ошибку транзакции, не отключая проверки.
Справочник: [pacman(8)](https://man.archlinux.org/man/pacman.8.en).

## Новый бэкап

```bash
./scripts/backup-packages.py
./scripts/backup-settings.sh
```

Для бэкапа настроек нужен Python 3 и tar с zstd. Для сборщика пакетов нужны Python 3.11+, pyalpm, pacman и bsdtar. Для интерфейса восстановления пакетов нужен Python 3. Сборщик ищет готовые архивы в `pacs`, кэше pacman, yay/paru
и Downloads. Недостающие репозиторные архивы скачивает с настроенных зеркал и
проверяет по SHA256 из базы pacman. Системную базу и установленную систему не меняет.
При отсутствии точной версии не подменяет её другой и записывает `missing.json`.
AUR-бинарники берутся из локальных кэшей: PKGBUILD сам по себе не является пакетом.
Если AUR-архива нет, предварительно соберите его обычным пользователем и повторите
сборщик. Чужой PKGBUILD автоматически от root не запускается.

Для хранения нескольких снимков:

```bash
./scripts/backup-packages.py --output backups/новый-снимок
./scripts/backup-settings.sh backups/новый-снимок
```

Повторный запуск в тот же каталог обновляет его индекс. Маркер `COMPLETE` появляется
только после сохранения всех пакетов; он подтверждает полноту **пакетов**, а не home
или системных настроек. `manifest.json`, `installed.txt`, `explicit.txt`, `foreign.txt`
и `os-release` описывают снимок. Каталоги `packages/repo` и `packages/foreign`
содержат готовые пакеты. Foreign включает AUR и пакеты вне репозиториев.

## Данные и настройки

`home-settings.tar.zst` содержит скрытые файлы и папки из home: настройки, авторизации,
данные приложений, конфигурацию и userdata Steam согласно выбранным исключениям.
Каталог `.local/share/Steam/steamapps` целиком (игры, Proton-префиксы compatdata
и shadercache), основные кэши и корзина исключены.
Точный список исключений: `home-excludes.txt`; входные папки: `home-files.list0`.
Обычные Documents/Downloads/Desktop и другие не скрытые каталоги не входят в этот
архив. Символические ссылки сохраняются ссылками, содержимое внешних целей не копируется.

Архив содержит личные данные и токены, поэтому создаётся с закрытыми правами доступа.
`home-backup-status.txt`: 0 — tar завершился без ошибок, 1 — во время чтения менялись
файлы (см. `home-backup.log`). Для согласованного снимка закрывайте приложения перед
бэкапом. Обычная файловая копия работающих приложений не гарантирует согласованность
их баз данных. Нулевые файлы-заглушки Steam с правами 000 сохраняются по метаданным
в `home-empty-files.tar` и восстанавливаются вместе с домашним архивом. Если
`home-backup-status.txt` равен 2, смотрите `home-backup-note.txt`: архив не следует
считать полным без проверки и объяснения ошибок чтения.

Архив выбранных системных настроек требует sudo:

```bash
./scripts/backup-system.sh
```

Не распаковывайте весь `/etc` поверх новой SteamOS без разбора: там есть настройки
загрузки и дисков текущей системы. Для изучения архива: `sudo tar -tf ...`.

## Индикация работы

Интерфейс `[ DECK / REC ]` показывает этапы, таймер и итог работы.
`[CMD]` показывает запускаемую команду; ниже видны её выполнение и последний
результат без потока однотипных строк. Полный вывод хранится в указанном журнале.
Проверка SHA256 показывает реальное число проверенных архивов / всего и число
ошибок. Вычисление сумм при бэкапе тоже показывает обработано / всего.
При архивировании и распаковке видны размер выходного архива (при создании)
и последнее имя файла из вывода tar. Поиск и сохранение пакетов показывают
текущий пакет; при скачивании — последнюю активную HTTP-загрузку.
При обработке пакетов видны процент и примерное оставшееся время этапа.
При архивировании показываются таймер и размер записанного сжатого архива:
общий объём заранее неизвестен, поэтому процент и ETA не выдумываются.
Время отдельных скачиваний и установки pacman заранее неизвестно.
Перед успешным завершением записи выполняется `sync -f` для накопителя.
Дождитесь `[OK] … Скрипт закончил работу` и возвращения приглашения терминала;
при `restore-all.sh` — сообщения о завершении всех выбранных этапов.
После этого можно закрыть терминал и штатно выключить Steam Deck.

Подробности архивации лежат рядом со снимком в `system-backup.log` и
`home-backup.log`; журналы восстановления — в `/tmp/rec-*`.
При ошибке выводятся последние строки журнала. Без TTY интерфейс печатает
обычные строки без управляющих кодов. `terminal-ui.sh` и `terminal-ui.py` —
общие помощники интерфейса; переносите их вместе со скриптами.
Python 3 теперь нужен также для интерфейса восстановления.
Старый комплект `backups/legacy` удалён при уборке; архивы вне индекса перенесены в `incoming/`.
Код 3 у `backup-settings.sh` означает сохранённый архив с менявшимися файлами;
другие ненулевые коды означают ошибку.

## Состав бэкапа, место и перенос

В меню «Настроить состав бэкапа» A переключает крупные категории. Выберите
«Сохранить и вернуться», чтобы применить изменения. По умолчанию исключены игры,
префиксы Steam, shadercache, дополнительные Proton, пользовательские и системные
Flatpak-установки/рантаймы, кэши и корзина. Данные приложений `.var/app`, `/etc`
и `/usr/local` включены. Можно отдельно исключить свои папки home: A открывает,
Y отмечает исключение, B возвращает. Размеры считаются в фоне; если оценка занимает
больше пяти секунд, это отмечается вместо выдуманного размера.

Настройки хранятся рядом с меню в `backup-options.json`. Также можно вручную
добавить относительные пути в `exclude_home` и `exclude_system` (`etc/...`,
`usr/local/...` для системы). При подготовке создаются точные списки файлов и
исключений `home-*` / `system-*` рядом со снимком.

Перед архивированием оценивается несжатый объём с учётом исключений. Требуется
место под новый архив плюс 1 ГиБ запаса, пока предыдущий архив остаётся на диске.
Оценка консервативная: сжатие заранее неизвестно. При падении свободного места
ниже 1 ГиБ запись останавливается. Не прерывайте успешный бэкап до сообщения
о завершении. После прерывания `.part` не является готовым снимком; его можно
удалить, когда связанные tar/zstd завершились.

Комплект переносится целиком: `rec.sh`, `Deck Recovery.desktop`, `scripts/`,
`backup-options.json`, `backups/` и при необходимости `incoming/` и `tests/`.
Пути вычисляются относительно расположения комплекта. Ярлык использует своё
местоположение через `%k`, без привязки к имени SD-карты или USB-диска.
`pacs` — относительная символическая ссылка. При переносе одного снимка берите
его собственные меню, скрипты и настройки вместе с архивами и индексами.

Первый просмотр архива читает его целиком для индексации заголовков, без
распаковки файлов на диск. B отменяет индексацию. Результат хранится рядом
в `*.index.json`; повторное открытие использует индекс, пока размер и время
изменения архива совпадают. Размер архива — сжатый, размеры дерева — несжатые.

## Язык и публикация кода

Интерфейс поддерживает русский и английский. В меню «Язык / Language» можно
выбрать Auto, Русский или English; выбор сохраняется в `ui-settings.json`.
Автовыбор учитывает `LC_ALL`, затем `LC_MESSAGES`, затем `LANG`: русская локаль
даёт русский, остальные — английский. Принудительный язык только на один запуск:

```bash
./rec.sh --lang en
./rec.sh --lang ru
./rec.sh --lang auto
```

Для отдельных скриптов подходит `REC_LANG=en`. Вывод pacman, tar и других внешних
команд остаётся на их собственном языке. `backup-options.json` автоматически
создаётся с безопасными стандартными исключениями, если отсутствует; существующие
настройки не перезаписываются.

`.gitignore` исключает снимки, `pacs`, `incoming`, архивы, журналы, временные файлы,
настройки пользователя и Python-кэши. Для публичного репозитория предназначены
код, переводы, тесты, ярлык и документация. Игнорирование не удаляет данные,
которые уже были добавлены в историю Git. Ничего автоматически не публикуется.

## Проверка скриптов

```bash
REC_LANG=ru python3 -m unittest discover -s tests -v
bash -n rec.sh scripts/*.sh
```

Тест проверяет выбор старой/равной/новой версии, epoch и pkgrel, отсутствующий пакет,
пробелы в пути, повреждённый архив и незавершённый бэкап. Реальная установка в тестах
не производится.
